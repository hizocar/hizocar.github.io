Class 1 · Your first web with Claude Code

By 14:30 you have a web for your own idea at a public address, a six-slide HTML deck about it, and a skill of your own that Claude uses every time you ask for a page.

Day 1 · Sunday 29 November 2026 · 08:00 to 14:30 You build: your own web, live on Vercel Milestone: M1 brief, due Sunday 13 December

Today is a workshop. You will spend most of it typing to Claude Code about your own idea: a business, a side project, a service, a portfolio. Each idea is explained in a few minutes and then you do it for real. Nothing on this page needs to be read before class except the setup guide.

How to use this page
  • Keep it open in your browser next to VS Code. Follow the parts in order; each one says how long it takes.
  • A box headed You, to Claude is a prompt. Copy it, replace the words in [brackets] with your own, and paste it into Claude Code.
  • The slides projected in the room are here. They are themselves an HTML file, the same kind you will make at 13:15.
  • Two rules for the whole course. Never paste a password, an API key or someone else’s personal data into Claude. Never publish a claim about your business you cannot defend.

What you leave with today

  • A web for your idea, built by directing Claude Code in plain language, open on your phone at your-web.vercel.app.
  • A six-slide presentation about it, in one HTML file, published at the same address.
  • A skill of your own, my-brand, that makes every future page and slide come out in your colors and your tone.
  • The habits that keep you in control of an agent: plan first, read the permission, one change at a time, go back when it goes wrong.

1 · Live demo

The instructor starts from an empty folder and, in about ten minutes, has a page open on a phone at a public address. Do not copy the clicks. Notice the order: describe, ask for a plan, read it, build, look at it, one change, publish. You will repeat that order all day.

2 · Setup check

Open a terminal (in VS Code: Terminal → New Terminal) and run the five tests of the setup guide. Type one line, press Enter, read the answer, then the next.

Test It passes when
1. code --version it shows a number
2. git config --global user.email it shows the email of your GitHub account
3. node -v it shows v22 or higher
4. claude, then inside it /status, then /exit your Claude account appears
5. The panel the Spark icon (✻) or ✻ Claude Code in the status bar at the bottom of VS Code opens the Claude Code panel

If a test fails, the setup guide has the fix. If it still fails after ten minutes, sit with a neighbor and work in pairs on their laptop until the break; the instructor fixes yours then.

Then create the folder of your project, here called mi-web: choose your own name, lowercase, no spaces, no accents. It goes in Proyectos, outside Desktop, Documents, iCloud, OneDrive or Google Drive, which sync files while Claude is writing them.

In the terminal · Mac
mkdir -p ~/Proyectos/mi-web && code ~/Proyectos/mi-web
In the terminal · Windows
mkdir $HOME\Proyectos\mi-web; code $HOME\Proyectos\mi-web

A new VS Code window opens on the empty folder. Open the panel from ✻ Claude Code in the status bar at the bottom (or ⌘/Ctrl + Shift + P, type Claude Code, choose the command that opens it). Do not create any file yourself: the folder must stay empty until Claude creates the project. Claude works inside the folder you opened: it does not see the rest of your computer unless you let it.

3 · How it works

Seven ideas, each one on a slide and in a few lines here. Three of them come with a three-minute try in your own panel.

A model predicts the next piece of text

Claude writes by predicting the most likely next piece of text, very well. It does not look facts up, so it can be fluent and wrong at once. Fluent is not the same as true: when it says “done”, open the page and look.

Try (3 min). Ask Claude for three taglines for your idea. Ask again with the same words, and compare. Same question, different answers: it predicts, it does not retrieve.

Tokens are what you pay for

Text is cut into tokens, about three quarters of a word each. Your Pro plan has a usage limit counted in tokens: it resets about five hours after your first message, and there is also a weekly limit. Long, wandering conversations spend it fastest, because Claude re-reads the whole conversation at every step. Start a new conversation when you change task.

The context window is its working memory

Claude sees only the current conversation: your messages, the files it opened, the output of its commands. What is not there, it does not know, including yesterday. What must last goes in CLAUDE.md, which you create at the end of the morning.

It can be confidently wrong

Try (3 min). Ask for three facts about your market, with their sources. Open one source. Is the fact really there?

A chat answers; an agent works

A chat assistant gives you text to copy. Claude Code is an agent: it opens files, writes them, runs commands, reads the errors and tries again, on your laptop, until the job is done. That is why it asks permission, and why you can stop it at any moment with Esc.

Try (3 min). Ask: “What is in this folder, and what would you need from me to build my web?” Watch it look before it answers. Do not let it create anything yet: the folder must stay empty for the lab.

A good request: context, goal, limits, then a plan

Claude Code is like a very capable new colleague who knows nothing about your project. Tell it what you would tell that colleague.

Weak

"Make me a website for my consultancy."

No audience, no goal, no limits. Claude will invent all of them, and you will spend the next hour undoing its guesses.

Strong

"I run Norte Advisory, a two-person consultancy that helps family businesses in Antofagasta prepare for a bank loan. Goal: a visitor understands what we do in ten seconds and books a call. Audience: owners aged 40 to 65, reading on a phone. Style: sober and warm, no purple gradients. Use Next.js with Tailwind, ready for Vercel. No database yet. Before writing code, ask me what you need and propose a plan."

The last sentence matters most: plan first, code after.

Plan mode and permissions

Plan mode. In the panel, click the mode indicator under the prompt box and choose Plan. (In the terminal, Shift + Tab cycles the modes.) In plan mode Claude only reads and proposes; it touches nothing. You read the plan, ask for changes, and approve it. Use it whenever a change touches more than one file or you are not sure what you want.

Permissions. Before creating a file or running a command for the first time, Claude asks. At the beginning, read every request.

Claude asks to… Your answer
create or edit files in your project Yes
run npm install … or npm run dev Yes. For commands that repeat, Yes, and don’t ask again
run anything with rm, sudo or git push --force, or touch files outside your folder Stop. Ask it: “why do you need this?”
write in ~/.claude/skills, when you create your own skill at 13:30 Yes. The one exception: personal skills live there

Practice · How it works

Claude says your contact form "now works". What do you do next?

Fluent is not the same as true. Judging the result by using it is your part of the loop, and it is the part nobody can do for you.

After two hours on the home page you start the deck in the same conversation, and Claude gets slow and confused. Why?

The context window is working memory. A new task deserves a clean one; what must survive goes in CLAUDE.md.

Claude asks permission to run rm -rf ~/Documents/old. What is the right answer?

rm, sudo, a forced push, or anything outside your folder: stop and ask. An agent with your permissions can do anything you can.

4 · Lab 1: your web

What you build in the next 75 minutes

Alone, on your own idea. The instructor circulates. If you are stuck for more than five minutes, raise your hand.

  1. Open your brief (2 min). The five lines you wrote at home: what your idea is, who it is for, the one thing a visitor should do, how it should feel (two sites you like), and what you do not want. No brief yet? Write it now, five lines.
  2. Switch to plan mode and send the first prompt (5 min). Use the prompt below with your brief in it.
  3. Answer its questions and read the plan (10 min). If the plan adds things you did not ask for, such as a login, a blog or a database, say: "Remove X for now; keep the first version to the brief." Approve when it matches.
  4. Let it build, reading each permission (18 min). Creating a Next.js project downloads a lot and asks several permissions. It is slow on a shared wifi: be patient, and do not start another task meanwhile.
  5. Open it (5 min). Ask: "Start the development server and give me the URL." Open http://localhost:3000. That is your web, visible only on your laptop. It updates by itself whenever Claude changes a file.
  6. Test it like a visitor (10 min). Read it as your audience would. Check every claim Claude wrote about your business: prices, promises, numbers, names. It invents plausible ones; remove what is not true. Then make the browser window narrow, like a phone. Write down the three things you like least.
  7. One change at a time (15 min). Fix the three things, one prompt each, looking at the page after each one.
  8. Go back once, on purpose (5 min). Ask for a change you do not like, then undo it: hover over your message in the panel, press the rewind button and choose Rewind code to here. (In the terminal, /rewind or Esc twice.) This is how you leave a wrong path in seconds.
  9. Save your progress (5 min). Ask: "Commit everything with the message 'first version'." A commit is a snapshot you can always return to.
You, to Claude · the first prompt (in plan mode)
I want to create the website for [my idea, in one sentence]. Goal: [the one thing a visitor should do: write to me, book a call, sign up for the list]. Audience: [who they are], reading mostly on a phone. Style: [two or three adjectives]. Sites I like: [one or two links]. Avoid: [what you do not want]. Sections: [three to five sections]. Use Next.js with Tailwind, ready to publish on Vercel. Create the project directly in this folder, not in a subfolder. No database and no login yet. Before writing code, ask me the questions you need and propose a plan.
You, to Claude · one change
One change, nothing else: [what you want, as precisely as you can, for example: the headline is too long, make it under eight words and keep its meaning]. Keep everything else as it is. When you finish, tell me in one sentence what you changed.
You, to Claude · when something looks wrong
On a phone-sized window, [exactly what you see, for example: the menu covers the headline and I cannot close it]. On a wide window it looks fine. First explain in plain words what you think is happening. Then fix it and tell me how to check.

Describe what you see, not what you think the code should do. “The button does nothing when I tap it” beats “fix the JavaScript”. If the same error comes back three times, stop asking for fixes: press Esc, rewind to before the problem started, and ask for the change differently.

5 · Skills and memory

Skills: manuals Claude opens when the job needs them

A skill is a folder with instructions, and sometimes scripts, for one kind of job: designing an interface, planning a feature, deploying. Claude reads only each skill’s one-line description until a task matches, then loads the whole manual. Skills come grouped in plugins. Install one from Anthropic’s official catalog, for design. Do it in the VS Code terminal, where the catalog is already set up:

In the VS Code terminal · type claude, then each line inside it, one at a time
claude /plugin install frontend-design@claude-plugins-official /exit

Go back to the panel. If it says Restart Claude to apply plugin changes, do it. Type /skills to see what you now have; /plugins in the panel manages them. A plugin can run commands on your computer: install only from the official catalog or from authors you know, as you would with any program.

You, to Claude · the redesign (20 min)
Use the frontend-design skill to improve the design of my home page. First propose two different visual directions in a few lines each, and wait for me to choose.

Choose one, look at the result on a narrow window, and ask for one or two changes.

CLAUDE.md: the project’s memory

Claude does not remember earlier conversations. What it must always know goes in a file called CLAUDE.md at the root of your project, loaded at the start of every conversation. Create it now: type /init in the panel, or simply ask “Create a CLAUDE.md for this project.”

Open the file and add a few lines of your own. The most useful section is the last one: every time Claude makes a mistake you never want repeated, tell it “add this to CLAUDE.md so it does not happen again”.

An example · CLAUDE.md
# Norte Advisory web ## What it is The site of a two-person consultancy: what we do, for whom, book a call. ## Rules - Write the site's texts in Spanish; talk to me in English. - Stack: Next.js + Tailwind, published on Vercel. - For design, use the frontend-design skill. - Never put keys or passwords in the code. ## Rules that came from real mistakes - The phone layout is checked before saying "done".

Commit again: “Commit everything with the message ‘design and CLAUDE.md’.”

6 · Publish

Push to GitHub (15 min). Two steps, in this order. First, ask Claude to check:

You, to Claude · before the first push
Check that nothing I am about to upload contains keys, passwords or .env files, and that everything is committed. Do not push.

Then, yourself: open Source Control in VS Code (the branch icon on the left, or Ctrl + Shift + G), press Publish Branch and choose Publish to GitHub private repository. The first time, VS Code asks you to sign in to GitHub in the browser.

Import in Vercel (15 min). Go to vercel.com/new, signed in with GitHub. Find your repository, press Import, change nothing, press Deploy. In one or two minutes you have an address like mi-web.vercel.app. If your repository is not in the list, choose Adjust GitHub App Permissions, give Vercel access to all repositories (or to this one), save, and come back.

Open it on your phone (5 min). Send the address to yourself and open it. Then make one small change with Claude, commit it, push it (Sync Changes in Source Control), and watch Vercel publish it by itself in about a minute.

One rule from real projects: what is live must be in GitHub. Commit and push first, always, so that the next automatic deploy does not undo your work. (Keys come on Day 2, with their own rules.)

If the deploy fails, your web is not broken: Vercel keeps showing the last version that worked. Copy the error from the Vercel page and give it to Claude: “The Vercel build failed with this error: [paste]. Explain the cause in plain words, fix it, and run npm run build before I push again.”

7 · An HTML deck in five minutes

A presentation does not need PowerPoint. A single HTML file with large type and arrow-key navigation opens in any browser, on any projector and on any phone, and Claude writes one in a couple of minutes. The deck projected in the room today is one of these files.

You, to Claude · the deck
Create a 6-slide HTML presentation about my project in a single file, public/slides.html. Slides: the problem, who it is for, what my web does, how it works, why now, what I need. One idea per slide, large type, my site's colors, arrow keys to move, works on a phone. No external libraries.

Open http://localhost:3000/slides.html. Fix the one slide you like least with a single prompt. Commit and push: the deck is now public at mi-web.vercel.app/slides.html, and that is the link you share. Files in the public folder are published exactly as they are, at the root of your address.

8 · Your own skill: my-brand

You have told Claude your colors and your tone several times today. Write them once, as a skill, and every future page, slide and text comes out right without asking. A personal skill lives in ~/.claude/skills/ and works in all your projects.

In the VS Code terminal · type claude, then each line inside it, one at a time
claude /plugin install skill-creator@claude-plugins-official /exit
You, to Claude · create the skill (15 min)
Use skill-creator to create a personal skill called my-brand with my colors ([#XXXXXX], [#XXXXXX]), my fonts ([font names]) and the tone of my texts: [close, no jargon]. Its description must say to use it whenever I ask for a page, a slide or a text for my project. Save it in ~/.claude/skills/my-brand, as a personal skill, not inside this project. Do not create test cases or run evals: just write the SKILL.md and show it to me.

Claude will ask to write outside your folder, in ~/.claude/skills. This is the one exception to the permission rule: answer yes. Then read what it wrote: in the terminal, code ~/.claude/skills/my-brand/SKILL.md. It is plain text, and its first lines (the description) are what Claude reads to decide when to use it.

Test it (10 min). Start a new conversation (/clear, or the new-conversation button of the panel) and ask: “Make me a one-page price list for my project.” Do not mention colors or tone. If the result comes out in your brand, the skill works. If /skills does not list it, restart the panel. If it is listed but not used, ask Claude to make its description more specific.

When something goes wrong

What you see What to do
command not found: code on a Mac In VS Code: ⌘ + Shift + P, type Shell Command: Install ‘code’ command in PATH, press Enter.
command not found: claude Close and reopen the terminal. Still failing on a Mac: run echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc and reopen. On Windows: add the folder the installer printed (usually %USERPROFILE%\.local\bin) to your PATH.
Windows: running scripts is disabled on this system In PowerShell: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned, answer Y, reopen the terminal.
Claude is going the wrong way Esc stops it at once. Then say what you want instead.
A change made things worse Hover over your message, press rewind, choose Rewind code to here. Or ask: “go back to the last commit”.
The same error keeps coming back Stop asking for fixes. Go back to before it started and ask differently, or ask: “Find the cause before changing anything: [what you see]”.
localhost:3000 does not open Ask Claude: “Start the development server and tell me the URL.” Another program may be using the port; it will pick 3001.
Works on your laptop, not on Vercel Copy the Vercel error to Claude and ask it to run npm run build locally before pushing again.
Vercel: No Next.js version detected The project was created in a subfolder. In Vercel’s project settings, set Root Directory to the folder that has package.json, and deploy again.
Your repository is not listed in Vercel Adjust GitHub App Permissions on vercel.com/new, give it access, save, come back.
“You have reached your usage limit” Pair with a neighbor until it resets; Settings → Usage on claude.ai shows when. Next time, /clear between tasks and keep conversations short.

Commands you will use

Command What it does
Mode indicator (panel) · Shift + Tab (terminal) Switch mode: Manual, Edit automatically, Plan
Esc Stop Claude now
Hover a message → rewind (panel) · /rewind (terminal) Go back to an earlier message, and optionally to the code as it was then
